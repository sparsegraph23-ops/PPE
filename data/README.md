# Data

Nothing in this directory is tracked by git. Everything here is either
re-downloadable, regenerable, or personal data that must not be committed.

## Layout

| Path | Contents | How to obtain |
|---|---|---|
| `raw/person/` | Person / half_person training set | Roboflow, see below |
| `raw/ppe/` | PPE (boot/helmet/jacket) training set | Roboflow, see below |
| `interim/` | Person crops and resized intermediates | Regenerated by `notebooks/20_infer_image.ipynb` |
| `processed/face_db/` | ChromaDB store of face embeddings | Rebuilt by `notebooks/22_face_enroll_identify.ipynb` |
| `external/images/set1,set2` | Demo stills for inference (16 + 50) | Committed history / supplied by the team |
| `external/videos/` | 4 construction-safety clips | Supplied by the team |
| `external/faces/` | Employee enrolment + test photos | **Biometric data — do not commit or share** |
| `benchmarks/cascade_testset_v1/` | 49-image labelled end-to-end test set | Roboflow, see below |

## Re-downloading from Roboflow

All three datasets live in the `fyp_23_2026-uor_foe` workspace. The API key must
come from the environment, never from a notebook cell:

```bash
export ROBOFLOW_API_KEY=...      # or put it in .env at the repo root
```

```python
from roboflow import Roboflow
import os

rf = Roboflow(api_key=os.environ["ROBOFLOW_API_KEY"])

# person detector training set  -> data/raw/person
rf.workspace("fyp_23_2026-uor_foe").project("ppe-detection-farqh").version(4).download("yolov11")

# PPE detector training set     -> data/raw/ppe
rf.workspace("fyp_23_2026-uor_foe").project("ppe_objects").version(5).download("yolov11")

# end-to-end benchmark set      -> data/benchmarks/cascade_testset_v1
rf.workspace("fyp_23_2026-uor_foe").project("test-dataset-mwcso").version(1).download("yolov11")
```

## Benchmark set

`benchmarks/cascade_testset_v1/` is the only labelled data the *cascade as a
whole* is scored on. It carries all 5 classes
(`boot, half_person, helmet, jacket, person`) in one label file per image, which
is what makes end-to-end evaluation possible.

49 images is small — treat the reported metrics as indicative, not tight. Growing
this set is the highest-value data work available.

## Privacy note

`external/faces/` contains photographs of identifiable people, and
`processed/face_db/` contains biometric embeddings derived from them. Both are
personal data under GDPR-style regimes.

These paths are covered by `.gitignore`, but the files **were already tracked
before the restructure** and an ignore rule cannot untrack existing files. They
are still in the index today. To stop tracking them (they stay on disk):

```bash
git rm -r --cached data/external/faces data/processed/face_db
```

Even then they remain in git history until it is rewritten. Do not copy them off
this machine without consent.
